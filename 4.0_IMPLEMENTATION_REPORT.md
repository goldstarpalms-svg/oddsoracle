**Date:** 20 Sept 2026 · **Commits:** `58ac2a1` (main build) + `f23d874` (sport intel + sitemap) on `main` · **Live:** https://oddsoracle-blond.vercel.app

## 1. What was built (by master-spec phase)

### Phase 1 — Audit (done before any change)
- Mapped all routes (`/`, `/board`, `/predictions/[sport]`, `/predictions/values`, `/slip`, `/live`, `/table-tennis`, `/track-record`, `/methodology`, `/search`, legal pages) and all APIs (`/api/predictions`, `/api/live`, `/api/book-code`, `/api/slip-code`, `/api/track-record`).
- Confirmed the **canonical snapshot already existed** (`lib/data-snapshot.json`, `dataDate` + `generatedAt`, WAT display via `freshness()` on every main page). Date audit: no page computes its own "today" — only two benign `new Date()` uses remain (booking-code label, sitemap `lastModified`).
- Prediction engine (Poisson + MC 10k + market/EV/Oracle Score + calibration + versioning + settlement) **untouched** — the 4.0 layer reads from its outputs.

### Phase 2 — Canonical data + automated QA
- **`scripts/qa-checks.mjs`** — 15 invariants, exit non-zero on violation:
  1. snapshot `dataDate` + `generatedAt` present & fresh (<96h)
  2. no row dated a different day than the snapshot (no yesterday-as-today)
  3. count reconciliation (football/basketball/tennis/other)
  4. every oracle prediction carries `model_version` + `data_timestamp`
  5. no VALUE/STRONG VALUE on negative edge
  6. no STRONG VALUE on stale (previous-day) prices
  7. high confidence never auto-promoted to value
  8. Oracle Scores within 0–100
  9. track-record rows all settled (score + final), cumulative stats **recompute exactly** from rows
  10. losses present (zero-loss check)
  11. all sport sections fully named (no fabricated/empty data)
- Wired into **prebuild** (blocks the Vercel build) and the **daily GitHub workflow** (blocks the auto-deploy commit step). All 15 checks pass on today's data.

### Phase 3 — Design system
- `globals.css` 4.0 layer: mono data font (tabular numerals), glass surfaces, glow, focus rings, subtle grid texture, `prefers-reduced-motion` respected (all animation/transition killed).
- **Desktop nav** per spec: Home / Oracle Board / Picks / Football / Basketball / Tennis / Table Tennis / Live / Slip Lab / Track Record / Methodology.
- **Mobile bottom bar** per spec: Home / Picks / Live / Slip / Oracle.
- Legacy signal chips re-themed to the dark terminal (consistent `STRONG VALUE/VALUE/HIGH CONFIDENCE/FAIR/PASS/AVOID` system).

### Phase 4 — Homepage + Oracle Model Board (signature)
- **Hero** rebuilt intelligence-first: "SPORTS INTELLIGENCE TERMINAL" eyebrow, system status strip (model version · live prices 35/40 · snapshot generation time WAT), CTAs **Explore the Oracle Board** / **Analyze a Slip**.
- **`components/OracleBoard.tsx`** — one row per scored event with:
  - model probability, market-implied probability, edge (pp), EV (%), Oracle Score (0–100, **tooltipped: not win probability**), engine consensus (2/2), data quality, model version, data timestamp, live-price flag;
  - filters: section, min edge (5/10/15pp), min confidence (60/70/80), league, free-text search;
  - sorts: sections / Oracle Score / edge / confidence / kick-off;
  - sections: **STRONG VALUE / VALUE / HIGH CONFIDENCE (80%+) / FAIR / PASS** — high-confidence picks with negative edge visibly sit in VALUE or get their real PASS treatment (the spec's 81%-vs-84.8% case is exactly how it renders);
  - expandable per-row evidence: model vs market breakdown, Monte-Carlo top scorelines, why-plus / why-minus, provenance line;
  - **deep link to Slip Lab** per row.
- **`/board`** page: full board + reading FAQ (what Oracle Score is, why high confidence can be PASS, what VALUE means, price freshness).
- Homepage embeds the board in compact mode (same component, same data — homepage count = board count by construction; QA cross-checks).

### Phase 5 — Sport intelligence
- **Table tennis = first-class** (`/table-tennis` + `components/TTBoard.tsx`):
  - **Sets O/U 3.5** per match — blends each player's real 4+-set rate (from the full 155,715-match Setka history) with the global rate. Verified by direct count: P(≥4 sets) = **69.91%** ({3 sets: 46,854 · 4: 58,454 · 5: 50,407}); global first-set O18.5 = 50.3%, O19.5 = 34.0%, avg sets 4.02.
  - **Real-data player dossiers** (expandable per match): record, win rate, last-20 win rate, points/set, points against/set, first-set win rate, last-10 form dots, small-sample flag; unknown player → "data unavailable rather than guessed".
  - Filters: player search, player dropdown, tournament dropdown (the "Setka filtering" requirement).
  - `fetch_setka.py` now emits `sets`, `profiles` and `global` into the daily JSON → flows through the bundle into the snapshot (no new fetches, same API).
- **`components/SportIntel.tsx`** on every sport page: two honest columns — what the model can see vs **UNAVAILABLE** (basketball: ratings/pace/rest/availability; tennis: surface/serve/return/breakpoint/form tables; football: lineups/injuries/xG; other: rosters). Nothing fabricated.

### Phase 6 — Slip Lab (pro workspace)
- **`?add=<event>` deep link** from every Oracle Board row ("Analyze in Slip Lab") — auto-adds the leg to the slip with a confirmation banner (name-based matching, no fabricated odds).
- **Weakest-leg detection** in the risk check: lowest-probability leg named with its edge, plus up to 2 **replacement candidates** (different match, ≥8pp stronger model read).
- **Final analytical read**: total odds, joint model probability, correlation warnings (same-match legs count once; same-league clustering), negative-edge flags, PASS-leg flags, price-vs-model comparison, and a plain-English **verdict** (clean / workable-but-risky / long-shot). Still never says "safe".

### Phase 7 — Track Record 2.0 (`lib/trackstats.ts` + rewritten `/track-record`)
- **Windows:** Last 7 / 14 / 30 / 90 days + all-time — settled, W–L, hit rate, units, ROI, avg odds (recomputed from rows per build; early windows are small samples and labeled as such).
- **P/L curve** (SVG, cumulative units, 1 unit per priced 1X2 call) with max-drawdown annotation (7.08u).
- **Calibration** (SVG curve: buckets vs perfect line, dot size = sample) + the existing bucket table with over/underconfidence gaps.
- **Skill scores:** Brier **0.2402** and log loss **0.6737** vs the 50/50 baseline log loss **0.3679** (n=56) — beats the baseline (coin-flip Brier is 0.25), stated as small-sample.
- **By market** (1X2 / O-U 2.5 / BTTS with n and ROI where priced) and **by sport** (Football 46 money picks vs NCAAF 10 win-rate-only — correctly separated).
- Raw audit trail: **all 56 settled rows, newest first, never edited** (losses included).
- Model version shown in the record; every stat carries its sample size.

### Phase 8 — QA + admin
- Automated QA suite (above) + CI wiring.
- **`/status`** — founder control center: **noindex, not in nav or footer, not in sitemap**. Shows canonical snapshot age, feed health (Forebet / OddsChecker live 35/40 / Setka / ESPN settlement / track record), model version + provenance, section counts, pipeline diagram.

## 7. Limitations (honest)
- Board rows currently cover **football** (the oracle-scored sport). Basketball/tennis/other sports are listed on their own pages with model data but not yet Oracle-rows — the board's data shape already supports them.
- Track-record **by-signal / by-edge-bucket / by-model-version** slices: rows predate per-row signal storage; 1X2/O-U/BTTS market slices, sport slices, windows, calibration and skill scores are live. Signal-bucketing lands once settled rows carry oracle signals (next settlement cycle).
- Brier/log loss and windows are on a 56-row base (2 days) — all labeled with n.
- NFL board appears on game days from 25 Sep (forebet page exists; Cloudflare blocks sandbox probing but not the GH workflow).
